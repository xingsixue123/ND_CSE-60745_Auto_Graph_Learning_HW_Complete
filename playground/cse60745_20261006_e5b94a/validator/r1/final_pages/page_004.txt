Q3: GIN Implementation (6 pts)
class MyGINConv(MessagePassing):
"""GIN: h_i’ = MLP((1 + eps) h_i + sum_{j in N(i)} h_j)."""
def __init__(self, in_channels, out_channels):
super().__init__(aggr="add")
# sum is the injective multiset aggregator
self.in_channels = in_channels
self.out_channels = out_channels
self.eps = nn.Parameter(torch.empty(1))
self.mlp = nn.Sequential(
nn.Linear(in_channels, out_channels),
nn.BatchNorm1d(out_channels),
nn.ReLU(),
nn.Linear(out_channels, out_channels),
)
self.reset_parameters()
def reset_parameters(self):
super().reset_parameters()
for layer in self.mlp:
# nn.Sequential has no reset_parameters
if hasattr(layer, "reset_parameters"):
layer.reset_parameters()
nn.init.zeros_(self.eps)
def forward(self, x, edge_index):
# Open neighbourhood: (1 + eps) h_i is already the self term, so a self-loop
# would count the node twice.
edge_index, _ = remove_self_loops(edge_index)
agg = self.propagate(edge_index, x=x)
return self.mlp((1 + self.eps) * x + agg)
def message(self, x_j):
return x_j
The aggregation is "add" because GIN’s expressiveness argument rests on the aggregator being
injective on multisets; mean and max discard multiplicity and would give up exactly the property
the layer exists to have. Unlike Q1 this is the open neighbourhood: (1 + ϵ)hi is already the self
term, so remove self loops prevents a node being counted twice (the training graph carries no
self-loops, so this is defensive). ϵ is a learnable scalar initialised to zero, and reset parameters
walks the Sequential’s children because the container has no reset parameters of its own. The
MLP is Linear–BatchNorm1d–ReLU–Linear, as in the GIN paper; the harness runs full-batch, so
the batch statistics are taken over all 7,624 nodes at once, including the 666 all-zero rows, and
evaluation uses the running estimates.
GIN is the weakest layer on this task, and the unnormalised sum is the likely reason: at initialisation
its embedding norm tracks degree far more tightly than GCN’s (log–log correlation 0.87 against
0.63; the top degree decile carries 22.9× the norm of the bottom decile, against 2.1× for GCN).
A dot-product scorer reads that magnitude as relevance, so high-degree users are ranked first
regardless of the query.
Measured: val MRR 0.4433, val Hit@1 0.2870; test MRR 0.4417, test Hit@1 0.2793.
