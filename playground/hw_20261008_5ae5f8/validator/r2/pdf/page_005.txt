Ex. 3.8
(10 pts, 2 pts each) — five page replacement algorithms
FIFO. Keep the resident pages on a queue in load order; evict the one at the head, which has
been resident longest, and append the arrival at the tail. One pointer, no hardware support,
and no usage information at all — so a page in constant use is discarded simply for being old.
FIFO is not a stack algorithm and can show Belady’s anomaly, where giving it more frames
increases the number of faults.
FILO (first-in last-out). The complement, as the name is used here: the resident pages
form a stack and the victim is the most recently loaded one, so arrivals keep reusing the same
frame. As cheap as FIFO and far worse, because the newest page is precisely the one the current
locality has just demanded; it is thrown out at once while the rest of memory never turns over.
NRU (not recently used). Sort pages by their (R, M) bits into four classes, numbered 0
to 3 for (0, 0), (0, 1), (1, 0), (1, 1), and evict an arbitrary page from the lowest-numbered non-
empty class. R is cleared on every clock tick, so it means “referenced since the last tick”, while
M is left alone. Cheap, and it prefers a clean unreferenced page, which needs no write-back.
LRU. Evict the page that has gone unreferenced longest, on the assumption that recent
use predicts imminent use. Exact implementation needs work on every reference: a timestamp
written into the page-table entry at each access, a list reordered at each access, or an n × n
matrix of bits. LRU is a stack algorithm and so is immune to Belady’s anomaly; its cost is why
the approximations exist.
NFU (not frequently used). One software counter per page. At each clock tick the OS
adds that page’s R bit to its counter and clears R, and the page with the smallest counter is
evicted. It needs only the reference bit, but it measures frequency over a page’s entire lifetime
and never forgets, so a page that was busy early keeps a high score after going cold — the flaw
that aging removes (Ex. 3.5).
