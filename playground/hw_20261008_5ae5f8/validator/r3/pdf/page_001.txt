The constraint.
With no MMU there is no translation step: the address the CPU puts on
the bus is the physical address. The program is linked to begin at 0 and to run over a contiguous
range, so physical address 0 and the bytes above it must belong to the application, and the OS
cannot have them.
The layout.
Load the OS at the high end of RAM, growing downward from the physical top,
and the application at physical 0, growing upward: text, then data and bss, then the heap,
with the stack at the top of the user region growing down (Figure 1). The program owns the
whole of [0, F), where F is the bottom of the OS, so both of the CPU’s assumptions hold with
no translation and no relocation: the loader copies the executable to address 0 byte for byte.
Running a different program overwrites [0, F); the OS never moves.
