## Design decisions (before coding)
### Q1 LapPETransformer
- L = I - D^{-1/2} A D^{-1/2}, eigenvectors 1..LAP_K (skip the trivial one at index 0).
- n-1 < LAP_K -> pad columns with zeros.
- Scale eigenvectors by sqrt(n) so each PE channel has RMS 1 regardless of graph size.
  Without this the entries are ~1/sqrt(n) (0.011 on LastFM, where num_atom_types=0 and
  the PE is the ONLY input signal) and the input would be numerically dead.
- Sign ambiguity: random per-graph, per-channel sign flip while training, identity at eval
  (Dwivedi & Bresson / GraphGPS).
- Solver: dense numpy eigh for n <= 1024, scipy.sparse.linalg.eigsh otherwise (LastFM 7624).

### Q1 SPDAttention
- precompute: hop-by-hop frontier expansion. Dense bool matmul for small n (ZINC),
  sparse block BFS for large n (LastFM), capped at max_dist+1 hops there.
  Cross-component pairs set to -1 (unreachable) using connected_components, so "far"
  and "unreachable" stay distinguishable even under the cap.
- forward: CNAttention's dense path with bucket = clamp(d, max=max_dist), -1 -> max_dist+1.

### Q2 SparseSPDAttention
- Exphormer-style pair set: self loops + graph edges + a random 2k-regular expander
  (union of k random Hamiltonian cycles) + one virtual (global) node, both directions.
- forward: gather q/k/v per pair, bias = spd bucket + pair-type bias, segment_softmax
  grouped by the querying node, scatter-add the values.
- Virtual pairs get spd 0 from make_batch (it zeroes pairs touching a virtual node), which
  would collide with the real "distance 0" bucket -> route them to the unreachable bucket
  and give them their own pair-type bias instead.
- Compare >= 2 strategies on ZINC: local-only, local+virtual, local+expander+virtual (main),
  2-hop ball.
